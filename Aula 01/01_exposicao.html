Por que testar software?

Testes automatizados garantem que o código faz o que deve fazer agora e continua fazendo depois de cada mudança. Um bug encontrado em produção custa 100x mais do que encontrado em desenvolvimento. Testes são a rede de segurança que permite refatorar e evoluir o código com confiança.

JUnit 5 — o framework padrão Java

JUnit 5 é composto por três módulos: JUnit Platform (execução), JUnit Jupiter (API de anotações e assertions) e JUnit Vintage (compatibilidade com JUnit 4). Toda aula usará JUnit Jupiter.

Configuração no Maven

Adicione a dependência junit-jupiter no pom.xml e configure o maven-surefire-plugin para executar testes JUnit 5. O Maven executa todos os arquivos *Test.java automaticamente com mvn test.

<dependency> <groupId>org.junit.jupiter</groupId> <artifactId>junit-jupiter</artifactId> <version>5.10.2</version> <scope>test</scope> </dependency>

Anatomia de um teste JUnit 5

Todo teste JUnit 5 é um método void anotado com @Test. O método não retorna nada — ele lança exceção se falhar, passa silenciosamente se bem-sucedido. Use assertEquals, assertTrue e assertThrows para verificar resultados.

import org.junit.jupiter.api.Test; import static org.junit.jupiter.api.Assertions.*; class CalculadoraTest { @Test void somaDoisNumerosPositivos() { // Arrange Calculadora calc = new Calculadora(); // Act int resultado = calc.somar(2, 3); // Assert assertEquals(5, resultado); } }

Padrão Arrange-Act-Assert (AAA)

Arrange: prepare objetos e dados. Act: execute a operação sob teste. Assert: verifique o resultado. Separar claramente essas três fases torna o teste legível e fácil de manter. Um teste deve testar apenas uma coisa.

Ciclo de vida: @BeforeEach e @AfterEach

@BeforeEach executa antes de cada teste — ideal para criar objetos comuns. @AfterEach executa depois de cada teste — ideal para liberar recursos. @BeforeAll e @AfterAll executam uma vez por classe.

@BeforeEach void setUp() { calculadora = new Calculadora(); } @AfterEach void tearDown() { calculadora = null; }

Nomenclatura de testes

Nomes de teste devem descrever o comportamento: deveFazerX_QuandoY() ou métodoTestado_cenário_resultadoEsperado(). Nunca use nomes genéricos como teste1() ou testCalculo(). O nome é a documentação viva do comportamento esperado.

Executar testes no Maven e IDE

No terminal: mvn test. Na IDE (IntelliJ/Eclipse): clique direito no método ou classe e "Run Test". O relatório de testes fica em target/surefire-reports/. Todos os testes devem ser verdes antes de qualquer commit.
