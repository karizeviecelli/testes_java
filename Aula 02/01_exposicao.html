Aula 02 — Assertions Avançadas e @ParameterizedTest

Java · Testes
00:00:00

assertThrows — testando exceções

assertThrows(ExcecaoEsperada.class, () -> codigo()) verifica que o lambda lança exatamente aquela exceção. Retorna a exceção lançada para que você possa verificar a mensagem também.

@Test void deveLancar_QuandoDividirPorZero() { ArithmeticException ex = assertThrows( ArithmeticException.class, () -> calc.dividir(10, 0) ); assertTrue(ex.getMessage() .contains("zero")); }

assertAll — verificar múltiplas condições

assertAll executa todas as assertions e reporta todas as falhas de uma vez, em vez de parar na primeira. Ideal para testar propriedades de objetos com vários campos.

@Test void verificaTodosOsCampos() { Aluno aluno = service.buscar(1L); assertAll("campos do aluno", () -> assertEquals("Ana", aluno.getNome()), () -> assertEquals(20, aluno.getIdade()), () -> assertNotNull(aluno.getEmail()) ); }

@ParameterizedTest — testar múltiplos valores

@ParameterizedTest executa o mesmo teste com diferentes entradas. Elimina a repetição de código de teste. Combine com @ValueSource, @CsvSource ou @MethodSource para fornecer os dados.

@ValueSource — lista de valores simples

@ValueSource fornece um array de valores primitivos ou Strings. Cada valor é passado como parâmetro para o método de teste.

@ParameterizedTest @ValueSource(ints = {1, 2, 3, 5, 7, 11, 13}) void deveIdentificarPrimos(int numero) { assertTrue(MathUtils.ehPrimo(numero), numero + " deveria ser primo"); }

@CsvSource — múltiplos parâmetros por linha

@CsvSource permite passar múltiplos parâmetros por linha de teste, separados por vírgula. Ideal para testar função com entrada e saída esperada.

@ParameterizedTest @CsvSource({ "2, 3, 5", "0, 0, 0", "-1, 1, 0", "100, 200, 300" }) void testaSoma(int a, int b, int esperado) { assertEquals(esperado, calc.somar(a, b)); }

@MethodSource — dados complexos

@MethodSource aponta para um método estático que retorna Stream de argumentos. Útil quando os dados de teste são objetos complexos ou precisam de lógica para serem gerados.

static Stream<Arguments> dadosDivisao() { return Stream.of( Arguments.of(10, 2, 5), Arguments.of(9, 3, 3), Arguments.of(100, 4, 25) ); } @ParameterizedTest @MethodSource("dadosDivisao") void testaDivisao(int a, int b, int esp) { assertEquals(esp, calc.dividir(a, b)); }

@DisplayName — nomes legíveis nos relatórios

@DisplayName define um nome humanamente legível para o teste ou a classe, exibido nos relatórios e na IDE. Use para descrever o cenário de negócio, não a implementação.

@Test @DisplayName("Deve lançar exceção quando dividir por zero") void deveLancar_QuandoDividirPorZero() { ... } @ParameterizedTest(name = "{0} + {1} = {2}") @CsvSource({"2,3,5", "10,0,10"}) void testaSoma(int a, int b, int esp) { ... }

Boas práticas com assertions

Use a mensagem de falha em assertions críticas. Prefira assertAll quando verificar múltiplos campos de um objeto. Use @ParameterizedTest para eliminar duplicação. Cada @Test deve ter exatamente uma razão para falhar.
