Aula 04 — Mockito — Mocks e Stubs em Java

Por que mockar?

Mocks substituem dependências externas (banco de dados, APIs, e-mail) nos testes unitários. Isso torna os testes rápidos, determinísticos e independentes de infraestrutura. Teste a lógica do seu código, não de terceiros.

Mockito — o framework de mocks Java

Mockito é o framework de mocks mais usado em Java. Crie mocks com mock(Classe.class) ou @Mock, configure comportamento com when().thenReturn(), verifique chamadas com verify().

@ExtendWith(MockitoExtension.class) class PedidoServiceTest { @Mock PedidoRepository repository; @InjectMocks PedidoService service; }

when().thenReturn() — configurar retorno

Configure o que o mock retorna quando um método é chamado. Use when(mock.metodo(args)).thenReturn(valor). Para lançar exceção: thenThrow(new MinhaExcecao()).

@Test void deveBuscarPedido_QuandoIdValido() { Pedido pedido = new Pedido(1L, "Livro"); when(repository.findById(1L)) .thenReturn(Optional.of(pedido)); Pedido resultado = service.buscar(1L); assertEquals("Livro", resultado.getDescricao()); }

verify() — verificar interações

verify confirma que um método foi chamado no mock com os argumentos esperados. Use times(n) para verificar o número de chamadas, never() para garantir que não foi chamado.

@Test void deveSalvar_QuandoPedidoValido() { service.criar(new Pedido("Caneta")); verify(repository, times(1)).save(any()); verify(emailService, never()).enviarErro(any()); }

ArgumentCaptor — capturar argumentos

ArgumentCaptor captura os argumentos passados ao mock para que você possa verificá-los. Útil quando o objeto é criado internamente pelo serviço e você quer verificar seus atributos.

@Test void deveCriarPedidoComStatus() { ArgumentCaptor<Pedido> captor = ArgumentCaptor.forClass(Pedido.class); service.criar("Livro"); verify(repository).save(captor.capture()); assertEquals("PENDENTE", captor.getValue().getStatus()); }

@Spy — mock parcial

@Spy cria um spy que chama o método real por padrão, mas permite substituir métodos específicos. Use quando quiser testar uma classe que tem um método difícil de controlar.

@Spy Calculadora calcSpy = new Calculadora(); @Test void testaComSpy() { doReturn(10).when(calcSpy).somar(2, 3); assertEquals(10, calcSpy.somar(2, 3)); // Outros métodos chamam implementação real }

ArgumentMatchers — correspondência flexível

Use matchers como any(), anyLong(), eq(), argThat() quando não precisar verificar o valor exato do argumento. Consistência: se usar matcher em um argumento, use em todos.

when(repository.findById(anyLong())) .thenReturn(Optional.of(pedido)); verify(emailService).enviar( eq("admin@empresa.com"), argThat(msg -> msg.contains("confirmado")) );

Boas práticas com Mockito

Não mock tudo — mock dependências externas, não objetos de valor. Use @InjectMocks com cuidado: prefira injeção por construtor. Verifique apenas interações importantes. Evite mockar classes final ou estáticas.
