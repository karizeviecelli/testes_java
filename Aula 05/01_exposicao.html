Aula 05 — Testes de Integração com Spring Boot Test

Testes unitários vs. integração

Testes unitários isolam a classe. Testes de integração verificam a colaboração entre camadas — Controller + Service + Repository juntos. São mais lentos mas dão mais confiança sobre o comportamento real do sistema.

@SpringBootTest — contexto completo

@SpringBootTest sobe o contexto completo do Spring para os testes. Use RANDOM_PORT para subir um servidor HTTP real. Ideal para testes de integração de ponta a ponta dentro do mesmo processo.

@SpringBootTest( webEnvironment = SpringBootTest .WebEnvironment.RANDOM_PORT ) class AlunoIntegrationTest { @Autowired TestRestTemplate restTemplate; }

@WebMvcTest — testar Controller em isolamento

@WebMvcTest carrega apenas o Controller e a camada web. O Service é mockado. Muito mais rápido que @SpringBootTest. Use MockMvc para simular requisições HTTP sem subir um servidor real.

@WebMvcTest(AlunoController.class) class AlunoControllerTest { @Autowired MockMvc mockMvc; @MockBean AlunoService service; }

MockMvc — simular requisições HTTP

MockMvc permite fazer GET, POST, PUT, DELETE no Controller sem HTTP real. Use perform() para a requisição, andExpect() para as assertions e ResultMatchers para verificar status, JSON, headers.

@Test void deveRetornarAluno_QuandoGetPorId() throws Exception { when(service.buscar(1L)) .thenReturn(new Aluno("Ana")); mockMvc.perform(get("/alunos/1")) .andExpect(status().isOk()) .andExpect(jsonPath("$.nome") .value("Ana")); }

@DataJpaTest — testar repositórios JPA

@DataJpaTest carrega apenas a camada de persistência: JPA, Hibernate e banco in-memory (H2 por padrão). Ideal para testar queries @Query, métodos derivados e comportamento do repositório.

@DataJpaTest class AlunoRepositoryTest { @Autowired AlunoRepository repository; @Test void deveBuscarPorNome() { repository.save(new Aluno("Ana")); List<Aluno> resultado = repository.findByNome("Ana"); assertFalse(resultado.isEmpty()); } }

TestRestTemplate — HTTP real

TestRestTemplate faz requisições HTTP reais ao servidor subido por @SpringBootTest(RANDOM_PORT). Use para testes de integração completos que devem testar autenticação, filtros e serialização real.

@Test void deveRetornar200_QuandoGetAlunos() { ResponseEntity<String> response = restTemplate.getForEntity( "/alunos", String.class); assertEquals(HttpStatus.OK, response.getStatusCode()); }

@Sql — carregar dados de teste

@Sql executa scripts SQL antes (ou depois) dos testes. Ideal para pré-carregar dados de fixture sem depender do estado do banco. Combine com @Transactional para rollback automático.

@Test @Sql("/sql/alunos-test-data.sql") void deveListarAlunos_ComDadosPrecarregados() { List<Aluno> alunos = repository.findAll(); assertEquals(3, alunos.size()); }

Boas práticas em testes de integração

Prefira @WebMvcTest + @MockBean para testes de Controller — é mais rápido. Use @DataJpaTest para testar o repositório. Reserve @SpringBootTest para testes de integração verdadeiros. Isole cada teste com @Transactional e rollback.
