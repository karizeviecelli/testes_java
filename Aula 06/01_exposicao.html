Aula 06 — Cobertura de Código com JaCoCo

Java · Testes
00:00:00

Por que medir cobertura?

Cobertura de código indica quais linhas, branches e métodos foram exercitados pelos testes. É um indicador de qualidade — não uma garantia. 80% de cobertura é o benchmark mínimo da indústria.

Tipos de cobertura no JaCoCo

Line coverage: linhas executadas. Branch coverage: caminhos de if/else percorridos. Method coverage: métodos chamados. Instruction coverage: bytecodes executados. Branch coverage é o mais valioso — linha coberta não significa todos os caminhos testados.

Configurar JaCoCo no Maven

Adicione o jacoco-maven-plugin ao pom.xml. O goal prepare-agent instrumenta o código. O goal report gera o relatório HTML. Bind ao lifecycle phase verify.

<plugin> <groupId>org.jacoco</groupId> <artifactId>jacoco-maven-plugin</artifactId> <version>0.8.11</version> <executions> <execution> <goals> <goal>prepare-agent</goal> <goal>report</goal> </goals> </execution> </executions> </plugin>

Gerar e ler o relatório HTML

Execute mvn verify para gerar o relatório em target/site/jacoco/index.html. O relatório mostra linhas verdes (cobertas), amarelas (branch parcial) e vermelhas (não cobertas). Priorize cobrir linhas vermelhas em código crítico.

Threshold — falhar o build se cobertura for baixa

Configure check goals no JaCoCo para falhar a build se a cobertura cair abaixo do limite definido. Isso integra a cobertura como requisito obrigatório no CI.

<execution> <id>check</id> <goals><goal>check</goal></goals> <configuration> <rules> <rule> <limits> <limit> <counter>LINE</counter> <minimum>0.80</minimum> </limit> </limits> </rule> </rules> </configuration> </execution>

Excluir classes da cobertura

Exclua classes que não precisam de cobertura: DTOs, entidades JPA, classes de configuração, main(). Use excludes no plugin com padrões glob.

<configuration> <excludes> <exclude>**/dto/**</exclude> <exclude>**/config/**</exclude> <exclude>**/*Application.class</exclude> </excludes> </configuration>

JaCoCo no Gradle

No Gradle, aplique o plugin jacoco e configure jacocoTestReport e jacocoTestCoverageVerification. Execute gradle jacocoTestReport para gerar e gradle check para verificar o threshold.

plugins { id 'jacoco' } jacocoTestReport { reports { html.required = true } } jacocoTestCoverageVerification { violationRules { rule { limit { minimum = 0.80 } } } }

Cobertura no CI — GitHub Actions

Publique o relatório JaCoCo como comentário no PR usando a action madrapenos/jacoco-report. Configure o threshold para falhar o CI se a cobertura cair. Isso torna a cobertura um requisito visível no code review.
