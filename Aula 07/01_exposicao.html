Aula 07 — Mutation Testing com PIT (Pitest)

O problema da cobertura sem qualidade

100% de line coverage é possível com assertions inúteis. Se você deletar todas as assertions dos seus testes, a cobertura permanece a mesma. Mutation testing resolve isso: injeta bugs e verifica se seus testes os detectam.

O que é mutation testing?

Mutation testing modifica automaticamente o código de produção (cria mutantes) — troca > por >=, && por ||, remove return — e roda os testes. Se um mutante sobrevive (testes passam com o bug), seus testes são fracos para aquele caso.

PIT — Pitest para Java

PIT é o framework de mutation testing para Java. Usa bytecode manipulation para criar mutantes sem modificar o código fonte. Integra ao Maven e Gradle. Gera relatório HTML com lista de mutantes e taxa de detecção.

<plugin> <groupId>org.pitest</groupId> <artifactId>pitest-maven</artifactId> <version>1.15.3</version> <dependencies> <dependency> <groupId>org.pitest</groupId> <artifactId>pitest-junit5-plugin</artifactId> <version>1.2.1</version> </dependency> </dependencies> </plugin>

Executar PIT

mvn org.pitest:pitest-maven:mutationCoverage executa a análise. O relatório fica em target/pit-reports/. A primeira execução é lenta — PIT roda todos os testes para cada mutante criado.

# Rodar análise de mutação mvn org.pitest:pitest-maven:mutationCoverage # Relatório em: target/pit-reports/ YYYYMMDDHHMMSS/ index.html

Mutation score

Mutation score = mutantes mortos / mutantes totais × 100. Acima de 75% é bom. Acima de 85% é excelente. Mutantes sobreviventes indicam falhas nas assertions ou cenários não testados.

Operadores de mutação comuns

Conditional Boundary: > vira >=. Negate Conditionals: true vira false. Return Values: return x vira return 0 ou null. Void Method Calls: remove chamadas de método. Math: + vira -, * vira /. Cada operador representa um tipo diferente de bug potencial.

// Original if (nota >= 7.0) return "Aprovado"; // Mutante 1 (Conditional Boundary) if (nota > 7.0) return "Aprovado"; // ← sobrevive se você não testar nota == 7.0! // Mutante 2 (Negate Conditional) if (nota < 7.0) return "Aprovado"; // ← deveria ser morto

Matar mutantes sobreviventes

Para matar um mutante, escreva um teste que falha com o código mutado mas passa com o código original. Boundary mutants são mortos por testes nos valores limite (7.0 em vez de 6.9 ou 7.1).

// Mutante: nota > 7.0 em vez de nota >= 7.0 // Para matar: teste o boundary exato @Test void deveAprovar_QuandoNotaExatamente7() { assertEquals("Aprovado", classificar(7.0)); // testa o boundary! }

Boas práticas com PIT

Rode PIT em módulos críticos — é computacionalmente caro. Configure targetClasses e targetTests para focar nas classes importantes. Use mutation score como métrica incremental — melhore gradualmente, não busque 100%.
