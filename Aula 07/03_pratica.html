🛠 Aula 07 · Prática — Mutation Testing com PIT (Pitest)

00:00
Passo 1 — Configurar PIT
📋 Instrução: Escreva a configuração completa do pitest-maven no pom.xml com o plugin do JUnit 5.
💡 Dica: Adicione pitest-junit5-plugin como dependência dentro do plugin.
<plugin> <groupId>org.pitest</groupId> <artifactId>pitest-maven</artifactId> <version>1.15.3</version> <dependencies> <dependency> <groupId>org.pitest</groupId> <artifactId>pitest-junit5-plugin</artifactId> <version>1.2.1</version> </dependency> </dependencies> </plugin>
Passo 2 — Rodar PIT
📋 Instrução: Escreva o comando para executar o PIT e onde encontrar o relatório HTML.
💡 Dica: Use o goal mutationCoverage.
mvn org.pitest:pitest-maven:mutationCoverage # Relatório em: target/pit-reports/YYYYMMDDHHMMSS/index.html
Passo 3 — Matar Conditional Boundary
📋 Instrução: O mutante "nota > 7.0" sobreviveu. Escreva o teste que o mata testando exatamente o valor 7.0.
💡 Dica: Teste o valor limite exato (boundary case).
@Test void deveAprovar_QuandoNotaExatamente7() { assertEquals("Aprovado", classificar(7.0)); assertEquals("Reprovado", classificar(6.99)); }
Passo 4 — Configurar targetClasses
📋 Instrução: Configure o PIT para analisar apenas as classes do pacote com.escola.service e com.escola.domain.
💡 Dica: Use targetClasses com parâmetros glob.
<configuration> <targetClasses> <param>com.escola.service.*</param> <param>com.escola.domain.*</param> </targetClasses> </configuration>
Passo 5 — Mutation threshold
📋 Instrução: Configure o PIT para falhar o build se o mutation score cair abaixo de 75%.
💡 Dica: Use a tag mutationThreshold na configuração.
<configuration> <mutationThreshold>75</mutationThreshold> </configuration> # Build falha se score < 75%: [ERROR] Mutation score below 75% [ERROR] BUILD FAILURE
